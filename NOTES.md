# The Getaway (SCUS-97133) — getaway-decomp notes

Started 2026-08-27. Goal: mission 1 native on x86_64 Linux with right-stick camera.
Milestone 1 (done): right-stick car-camera orbit as a PCSX2 pnach, running at 60 FPS.

## Disc / binary
- `disc/` = the 12 files. `SCUS_971.33` 3.1 MB stripped R5900 ELF, GCC 2.9x, RTTI names survive.
- `PACK_EE.PAK` (2.58 GB) / `PACK_IOP.PAK` (1.90 GB, audio). Header `SceeWhPC`/`SceeWhPk`, build
  stamp, 2×u32, source path, then data. Bytes from abs offset 0x39 IDENTICAL in both -> fixed
  keystream over the TOC (unsolved; the reader is in the ELF, string `pack_ee.pak`).
- Ghidra 12.1.3 + ghidra-emotionengine-reloaded, project `ghidra/Getaway`. Wrappers
  `~/.local/bin/ghidra`, `ghidra-headless`. Full decompile of all 7591 funcs in `ghidra/all/`.

## GCC 2.9x RTTI/vtable layout (cost an hour)
- `NNClassName` strings are referenced only from `__tf_<Class>()` which lazily builds the
  type_info in .bss. No pointer to the name exists in the image.
- vtable entries are 8 bytes `{delta, fptr}`; slot 0 = `__tf`, slot 1 = dtor. `scripts/rtti_scan.py`.
- Camera classes: CameraController base; Car/Crane/Player/Stealth/Target/SteepStair/FreeAim/
  Roll/Death/Scripted controllers. All 17 slots. `ghidra/vtables.txt`.

## Input path
- `Pad_ctor` = FUN_002a3388; pad objects 0x3dcd00 (port 0), 0x3dce80. `Pad::Update` = FUN_002a3458.
- Raw DS2 bytes -> descriptor table (`FUN_00278a28` builds it; type 3 = DS2 at 0x3dcbe8):
  op3 buttons(u16 @state+8), op5 stick axis -> float (-1..1, deadzone ±1 raw) into
  `((float*)*(state+0x50))[idx]`. idx: 0=RX 1=RY 2=LX 3=LY, 4..15 pressures.
- Port-0 controller state object = 0x3dc238, axes pointer at 0x3dc288.
- **No game code reads axes[0]/[1]** — right stick was unused. Left stick reader: FUN_0026d388.

## Car camera (CarCameraController_vf14 = per-frame update, 0x13c..0x13d)
- Final yaw in f23 at 0x13d164 (`jal sin`, delay slot `mov.S f12,f23`), cos at 0x13d170.
- Patch: 0x13d164 -> `jal 0x3d6df0`; cave (libpad error strings, error-path only) does
  f23 += RX*π, f12=f23, `j sin`. Generated by `patch/build_pnach.py`. Verified in-game.
- Look-back blend DAT_0035de9c (written in _vf3) rotates the forward vector pre-atan2.

## Camera v2 (GTA-style) — `patch/build_pnach.py`
- Cave 0x3d6d58..0x3d6e4c: `compute` (44 w) keeps a persistent angle at 0x3d6e48:
  angle += -rx*|rx|*3.5*dt (dt = DAT_003741fc), clamp ±π; |rx|<0.1 -> angle *= max(0, 1-6dt).
  Stubs: car (f23 @0x13d164) and on-foot (f22 @0x144e48, PlayerCameraController_vf3); stubs
  save ra in t9 (caller-saved, dead before the imminent sin call) and tail-jump into sin.
- v1 sign was flipped -> RATE is negative. EE COP1: 0x28 = max.s, 0x29 = min.s (I had them swapped;
  the Ghidra re-disassembly of the patched ELF caught it — always verify encodings that way).
- f0-f19 are free at both sites because a call is imminent; f20+ are live (f20 = distance on foot).

- **patch=1 (continuous) rewrites the word every vsync** — my persistent angle at 0x3d6e48 was being
  zeroed each frame, so the car orbit never exceeded rx*3.5*dt ("small angle, runs out"). On foot it
  hid the bug because the follow-cam integrates. State words must be `patch=0` (boot-once).
  Rule: a pnach is a memory *poker*, not a loader — every line runs every frame unless told otherwise.
- `TrackedPoint` (vtable 0x3c8de8, camera +0xf0 and the car's) = {+0 valid flag, +0x10 position xyz,
  +0x20 spatial-cell id, +0x24 vptr}. **No rotation in it.** Treating +0 as a quaternion blacked the
  world (v3, reverted; code kept in build_pnach.py behind ORIENT_ENABLED=False). Camera facing is
  derived elsewhere (look-at), so orbiting the position is sufficient.

## Camera v4 (current, 2026-08-27)
- On foot: right stick, STATE word deliberately `patch=1` (reset every frame) — per-frame offset
  -rx|rx|*3.5*dt that the follow-cam integrates. Adam preferred this over a persistent angle.
- Car: same small stick nudge + GTA III views: compute_car (cave B 0x3d6eb0) eases STATE2 (patch=0)
  toward L2:+pi/2, R2:-pi/2, both:pi, none:0 at min(12*dt,1). Buttons u16 at 0x3dc240 (bit0 L2, bit1 R2).
- Wide persistent orbit in the car looked wrong (camera facing is not a look-at at large angles) — dropped.

## Cutscene skip
- Runner FUN_0027edc0 (cut_sequence). Skip requires just-pressed(state,0x400) [FUN_0026d770 = edge,
  FUN_0026d738 = held, FUN_0026d820 = axis] AND FUN_0029a738(0x3aae28, id) = "seen before" bitfield.
- Patch: 0x27f6bc li a1,0x400 -> 0xc00 (adds Start); 0x27f6d8 jal seen_before -> li v0,1.
- Other gates still in place: DAT_0035590c==0, DAT_003932b4!=8, DAT_00397bfc==0, DAT_00392500 state.
- Button word layout: (rawbyte2<<8|rawbyte3): 0x100 sel,0x200 L3,0x400 R3,0x800 start,0x1000 up,
  0x2000 right,0x4000 down,0x8000 left; 0x1 L2,0x2 R2,0x4 L1,0x8 R1,0x10 tri,0x20 circ,0x40 X,0x80 sq.

## PCSX2 / performance
- CRC E21404E2 (= XOR of u32 words of the ELF; confirmed by PCSX2's gamesettings filename).
- pnach in `~/.config/PCSX2/cheats/E21404E2.pnach`; labeled group + `[Cheats] Enable = <name>`
  in the game ini (an unlabeled pnach disables PCSX2's bundled patches for the game).
- Bundled 60 FPS patch: `patch=1,EE,201F10E8,word,1000000B` (in FUN_001f0eb0, vsync wait).
- Legion Go 2 firmware default PL2(19W) < PL1(23W) -> APU flat 20W, cores 1.2 GHz -> 43% speed.
  Fix: gamezone profile `custom`, ppt_pl1_spl=30, ppt_pl2_sppt=32 -> 33W, 4.3 GHz, 100%.
  Measured @30W native: 60fps patch+EECycleRate3: EE 75-80%, GS 42-77%. 4x upscale: 73% speed.
  `~/.local/bin/getaway` applies the limits and launches.
